# ワイン「記憶の仲介」ハブ 設計書（2026-11-04）

## 1. 目的（なぜ作るか）

ワインの活動が、ai-org（自動実行）・Claude アプリのマーケティングのプロジェクト・手作業の資料の3か所に分かれてきた。
各所が「他で何を作ったか」を知らないため、内容が**同じではないが似て見える**生成物（特に ai-org が Pexels から取る B-roll、投稿テーマ）が出ている。
Obsidian の保管庫を共通の「記憶の置き場」にして、新しく作る前に誰もが確認し、作った後に必ず記録する。

## 2. ゴール／ノンゴール／アンチゴール

**ゴール**
- ai-org と Claude アプリが同じ台帳を読み書きし、似た動画・投稿テーマ・資料を重ねない。
- B-roll は「同じクリップ」だけでなく「似た見た目」も避ける。
- コーヒー部門の自動実行を止め、コーヒーは `AI会社` 保管庫に一本化する。

**ノンゴール**
- デスクトップの既存ファイル（約1.6GB）を移動・コピー・整理しない。台帳には場所へのリンクだけを書く。
- 既存の `AI会社` 保管庫は変更しない。
- Notion の「コンテンツ生成物」DB、既存の B-roll 重複防止（`output/.broll_used.json`）は置き換えない（補強する）。
- コーヒー関連のコード、バリスタのエージェント、過去の出力は削除しない。

**アンチゴール（動いても失敗）**
- 台帳がファイル単位に膨らみ、誰も更新・参照しなくなる。
- 台帳を確認せずに AI が作り、記録も残さない。
- パスワードや API キー類が保管庫に入る（`~/Desktop/CHIAVE` は索引にも入れない）。
- 保管庫の中身が Public リポジトリ（ai-org）にコミットされる。

## 3. 決まったこと（ユーザーの決定）

- 新しい保管庫を、ワイン用として別に作る。`AI会社` はコーヒー専用。
- コーヒー部門の終了は「自動実行を止めるだけ」。
- 台帳の単位は、シリーズ・講座の回・州（ファイル単位にしない）。
- 似て見える B-roll は ai-org が Pexels から自動取得する動画の問題で、デスクトップのリール素材とは別。
- Claude アプリは PC のファイルを直接読める。

## 4. 構成

### 4.1 保管庫（ビルダーの判断：場所と名前）
`~/Documents/ワイン台帳/`（Obsidian で開ける通常のフォルダ。ai-org リポジトリの外）

```
00_ルール.md          すべての AI が最初に読む決まり（確認→作る→記録）
01_台帳/
  シリーズ.md         リール・カルーセルのシリーズ（切り口・本数・場所）
  講座の回.md         講座の回ごと（0〜7、72〜76 など）
  州別.md             20州の旅の進み具合と場所
  投稿テーマ.md       投稿・note のテーマ（ai-org の自動抽出テーマも追記）
  配布物.md           LINE特典・講座特典（PDF・診断など）
  B-roll.md           ai-org が自動追記（取得日・キーワード・映像の説明・動画ID）
02_進行中.md          いま誰が何を作っているか（着手前に宣言、完了で消す）
03_決めごと.md        企画名「イタリアワイン、迷わない私になる」、講座案Bなど確定事項
04_プロモーション/    8日間プロジェクトの原稿・シート・Canvaへのリンク
```
各台帳の1行：`名称｜種類｜切り口(一言)｜作成日｜場所(パスまたはURL)｜使用状況`。

### 4.2 初期登録
デスクトップ「投稿内容・資料一式保存用フォルダー」（講座の回、20州、リール素材のシリーズ、LINEプレゼント、診断、trivia など）を、シリーズ・回・州の粒度で台帳に登録する（約18シリーズ、20州、講座の回10前後、配布物）。空フォルダ3つは「空」と記載。

### 4.3 ai-org の変更
1. **B-roll の類似回避**：`fetch_broll` が、取得した動画のキーワードと映像の説明（Pexels の動画ページURLに含まれる説明語）を `B-roll.md` に追記。取得時は直近の記録と説明語が近いクリップを候補から外し、別の候補を探す。既存の ID/md5 の重複防止は残す。
2. **エージェントの事前確認**：ワインの週次タスク（テーマ決定、動画素材生成、SNS投稿文など）のプロンプトに、台帳の要約（直近のシリーズ・テーマ）を参考情報として渡す。既存の「直近8件のテーマ」の仕組みと並べる。
3. **事後記録**：週次タスクが終わったら、台帳（投稿テーマ、B-roll）に追記する。追記は専用ファイルへの追記のみとし、人が手で編集するファイルとは分ける（衝突回避）。
4. **コーヒー停止**：`runner.py` のコーヒー関連の6つのスケジュール登録（月10:00、月10:30、火10:00、火12:00、火13:30 とExpress、金10:00）を、フラグ（例：`COFFEE_ENABLED = False`）で止める。コード・エージェント・出力は残す。`CLAUDE.md` の週次スケジュール表に「コーヒーは停止中（AI会社へ移行）」と明記。
5. **設定**：保管庫のパスは環境変数（例：`WINE_VAULT_PATH`）で指定し、未設定・保管庫が無いときは従来どおり動く（台帳が無くても止まらない）。

### 4.3 Claude アプリ側
- 保管庫フォルダへのアクセスをアプリのプロジェクトに許可する（ユーザーの操作）。
- `00_ルール.md` に「作る前に01_台帳と02_進行中を確認、着手時に02へ宣言、完了時に01へ追記」と書き、プロジェクトの指示から参照させる。

## 5. 制約
- ai-org は Public リポジトリ。保管庫は別フォルダに置き、コミットしない。台帳に秘密情報を書かない。
- 有料API（Higgsfield など）の動作は変更しない。

## 6. ビルダーに任せること
- 台帳の列やファイル名の細部、B-roll の「説明語が近い」の判定基準（共通語の割合など）、テスト方法。
- 初期登録の分類（どのフォルダをシリーズ／回／州に当てはめるか）。判断に迷ったものは「要確認」としてユーザーに渡す。

## 7. ビルダーとしての読み直し（自己チェック）
- 「台帳に載せる粒度」と「B-rollの類似判定の基準」は、方向は決まっていて詳細は任せてよい。
- 「Claude アプリに保管庫を見せる設定」はユーザー側の操作で、こちらは `00_ルール.md` を用意するところまで。
- 保管庫が無い環境でも ai-org が止まらないよう、失敗時は従来動作に落とす。
- 未決で、ユーザーにしか決められない点は、**初期登録の前に「保管庫の名前と場所（`~/Documents/ワイン台帳`）でよいか」の確認**のみ。
